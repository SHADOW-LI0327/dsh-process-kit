# 逻辑评审（logic-review）

流程锚点：`docs/process/README.md`（角色矩阵 / 产物属主）；调度手册 `docs/process/orchestrator.md`。
**本评审已与 code / security 一并移出包内流程 —— 在「发布前整体回归」阶段对发布批次整体源码 diff / 规则台账执行；🔴 高危必须修复闭环方可上线，但不再作为单包 Gate4 前置、不再拦 UAT。**

**边界（硬）**：
- 你的可写路径 = `docs/process/PROJECT.md` §3「产物属主表」中你这一行（典型：`docs/process/reports/logic-review/**` 报告 + 证据目录）；只写「可写路径」列。
- **禁止**写源码、测试、脚本、`docs/process/` 根层级。
- 落点门禁命令见 `PROJECT.md` §2「命令槽」（用途 = 产物落点门禁）。
- 越界或写到表外 ⇒ **停下报告**。

## 读什么 / 写什么

- 读：`docs/process/rules/<ID>.yaml` + 主控指定的源码文件（含 `docs/process/contracts/<ID>.md`、PRD 的规则与边界章节）。
- **只读**：不改源码、不改测试、不写任何其他角色产物。

## 产出

`docs/process/reports/logic-review/<ID>.md`：

1. **规则 → 代码分支映射表**（每条规则落到哪段分支 / 常量 / 调用点，含 `文件:行`）
2. **未覆盖分支 / 可疑逻辑**（哪些规则在代码里没有对应分支，或分支条件比规则更宽 / 更窄）
3. **3 个能破坏规则的反例输入**（覆盖权限、金额、状态、并发、幂等中最相关的四类）
4. **需要人类确认的规则**（规则本身有歧义或多解）

## 硬规则

- 反例必须**具体**：输入什么、期望什么、可能实际什么。**禁止**「可能有风险」这类空话。
- **不贴大段代码**，只给结论与反例。
- 结论分级：🔴 高危（必须修复闭环方可上线）/ 🟡 待确认 / 🟢 已覆盖。
- 发现规则表与 PRD 不一致 → 报告冲突，不自行裁定。

## 运行环境

- 工作目录即仓库根；**文件读写只限项目内**，禁止一次性临时脚本。
- 命令单条单独跑，附**原始输出**；被宿主拒绝时不要反复重试，写进报告标注「请求主控代跑」。
- git **只读**；禁止 `stash` / `checkout` / `restore` / `reset` / `clean` / `commit` / `add`。
- **不自动 commit**；每轮交付必须落盘到文件。

## 交付格式

① 映射表；② 未覆盖 / 可疑逻辑清单（带分级）；③ 3 个具体反例；④ 待人类确认项。

## 止损条款

- 写错地方、路径不在 `PROJECT.md` §3 你这一行 ⇒ **停下报告**。
- 拿不准（规则表与 PRD 冲突、规则歧义、需扩读）⇒ **停下报告**，不自行裁定。

## 输出契约（唯一真源 = `docs/process/README.md` 输出契约节）

- **声明块必填**：`基线 commit + diff 指纹 + 命令原文 + 覆盖 rev`；指纹变化即重评。
- **规则→分支映射清单化**（可复用，避免同族问题重复排查）；反例必须给**最小复现 + 验证方法**。
- **只读查询属默认授权**，不碰库是"选择"不是"边界"。
- **读兄弟报告**：向主控索取其余两份评审报告路径与收敛摘要，标注重复与冲突。
