# <ID> <标题> · UI 规格

> **本文件是什么**：把《设计与说明》里**触及 UI 的条目**翻译成**可验收的 UI 规格** —— 界面由哪些组件构成、有哪些交互状态、用户可见文案是什么。它是 test 写 UI 断言的**判据来源**。
> **本文件不是什么**：不是 PRD（判据在 PRD 的 `AC`）、不是契约（字段与签名在 `contracts/<ID>.md`）；**不写实现细节**（组件内部结构 / 状态管理选型 / CSS 类名 / 文件路径 / 接口调用细节）。
> **交付物是原型图，而原图是位图** —— dev 没法从图里机器可读地取色取值。**所以「具体数值」必须由本件的 §八 承担**：颜色 / 间距 / 字号字距 / 圆角全部给出**可直接取用的字面值**，否则 dev 只能靠肉眼对着图取色，那正是最容易走样的一环。原型图本身放在 `prototypes/<ID>/`（见 §八）。
> **权威来源**：需求核对件的裁定表（`R-NN`）与《设计与说明》。**不得在此发明新业务口径** —— 需要新口径时回流 PRD 待确认事项，由人裁定。
> **送审时机**：**随 Gate1 一并审**。它是判据来源，判据必须有人审过，故不另设停点、也不在 Gate1 之后补写。
> `status` 是 ui-spec 自有的次级状态位（`confirmed` = Gate1 已过 / 本件已定稿），**不是** PRD 状态机的值；权威状态位只在 `prd/<ID>.md`。
> **适用性**：仅**核对件声明 `uiDesign: required`** 的包需要本文件；`not-needed`（或未声明）的包不产生。那份「要不要做 UI 设计」的判断由**人在 Gate0** 做出（见 `input/_CHECK_TEMPLATE.md`），不由主控推断。

### 8.0 技术与手段（**必须写明；但整节都可以选择不用**）

> **本框架不绑定任何具体工具** —— 用什么出图、用什么导几何，由项目和角色自己定。
> 但**用了什么就必须写明**：默默用了某工具，后人既无法复现这份图，也判断不了几何门禁的结论算不算数。
> **不想用某个工具、甚至完全不出图也可以** —— 见下方「三条不使用路径」，照走并写清楚，**不算缺陷**。

| 项 | 值 |
| --- | --- |
| 出图工具 | `<名称 + 版本>`（例：`PhotoCraft CLI 0.5.0 (e5e3e3975)`）／`不使用` |
| 出图方式 | `<完整命令与关键参数，可复现>`／`不使用` |
| 输出规格 | `<如 1280×800 @ 72 ppi>`（**ppi 必须写** —— 字号单位是 point，随 ppi 缩放到像素） |
| 几何导出 | `<命令>`／`不使用（无几何证据，门禁不判）`。**交付前那次建议带 `--verify`**（重导一遍逐元素比 `bounds`，把「几何来自产物」从声明变成验证；做不到时它会直接失败而不是静默放行） |
| 分层源 | `<文件名>`／`不留（原因：…）` |
| 令牌来源 | 项目令牌 `<路径>` ／ 通用默认 `docs/process/ui/tokens.md` |

**三条不使用路径（都可走，都必须写明）**：

1. **不出原型图，只出规格** ⇒ §8.1 写「不产出原型图（原因：…）」；**§8.2 视觉数值表仍然必填** —— 它是 dev 唯一的取值来源。
2. **出图但不用几何门禁** ⇒ §8.0 几何导出写「不使用」并给原因（如工具没有可编程接口）。**没有几何证据时门禁不判红、只提示**；但**必须显式声明，不许默默不出**。
3. **整个 UI 设计都不做** ⇒ 这不是 §八 的事 —— 回到核对件把 `uiDesign` 写成 `not-needed`，**不产生本文件**，流程完全不变。

### 8.1 原型图（交付物）

> **交付物就是原型图**。落点 `prototypes/<ID>/`；**分层源文件与几何证据一并留下**，否则后续无法复核、也无法继续编辑。

| 文件 | 内容 | 是否必留 |
| --- | --- | --- |
| `<中文短名>-<ID>.png` | **原型图（交付物）**，一屏一张 | 必留（走路径 1 则写「不产出」+ 原因） |
| `<中文短名>-<ID>.psd`（或等价分层源） | 分层源文件，供后续精修 | 必留（同上） |
| `geometry.json` | **适配器从产物导出**的几何（`bounds` **禁手写**） | 用了几何门禁则必留 |
| `intent.json` | 作者意图：哪些元素应居中、内容区横向带 | 用到才留 |

> **多屏（一个包通常不止一屏）**：门禁支持 `geometry.json` 与 `geometry.<屏幕名>.json` **并存**，会逐屏判定。
> 对应的意图写 `intent.<屏幕名>.json`（**优先取同名，取不到才退回共用的 `intent.json`**）。
> 屏幕名用**中文短名**（如 `geometry.统计.json` / `intent.统计.json`），与 `UI-NN` 短名一致。
> 只产一屏时用不带后缀的 `geometry.json` / `intent.json` 即可。

> **文件名遵守中文短名纪律**（见总纲）：`<中文短名>-<ID>.png`，短名与本件 §一 的 `UI-NN` 短名一致，**不另起别名**。

### 8.2 视觉数值（**dev 直接取用，不要靠肉眼对图**）

> 令牌优先级见 `ui-designer` 技能：**项目自己的令牌 > 通用默认值**（`docs/process/ui/tokens.md`）。
> 下面每一项都写**字面值**；写"深灰""稍大"这类描述性词 = **不合格**。
> 取值必须与原型图**一致** —— 位置类可由几何门禁交叉验证，颜色类由人在 Gate1 比色核对。

| 类别 | 令牌 / 位置 | 字面值 | 用在哪 |
| --- | --- | --- | --- |
| 颜色 | `bg` | `#0d1117` | 页面底色 |
| 颜色 | `surface` / `border` / `text` / `muted` / `accent` / `success` / `warn` / `danger` | `<#rrggbb>` | <…> |
| 间距 | 卡片内边距 / 区块间距 / 内容区外边距 | `<N>px` | <…> |
| 字号 | 标题 / 正文 / 标签 / 辅助 | `<N>px` | <…> |
| 字距 | 按字号给（中文字距见 `tokens.md` 映射表） | `<N>`（1/1000 em） | <…> |
| 圆角 / 控件高 | 卡片 / 按钮 / 胶囊 / 输入框 | `<N>px` | <…> |

> **用了通用默认令牌就必须在此写明**（例如"本次采用 `docs/process/ui/tokens.md` 默认令牌，未使用项目专有令牌"）—— 让人知道这不是项目既有的视觉语言。
> **单位纪律**：字号单位是 **point，随文档 ppi 缩放到像素**；要 `1pt = 1px`，文档分辨率必须是 **72 ppi**（144ppi 下文字会被放大一倍，表现为"字挤在一起"）。
