# UI 布局配方（实测验证过的起点）

> 这不是"唯一正确的设计"，而是一份**已经过几何门禁验证的起点**：数字可以直接抄，也可以按项目改。
> 它的价值在于**省掉从零排版的那一轮返工** —— 从一份已知不重叠、不溢出、边距对称的骨架上改，比从空白画布开始稳得多。
> 每个数字后面都注明了"为什么是这个值"，**改的时候知道自己在动什么**。

## 通用骨架（1280×800 桌面端）

```
┌──────────────────────────────────────────────────────────────┐
│  侧边栏 240px   │            内容区（band）                    │
│                 │   ← 40px 外边距 →              ← 40px →     │
│  0 ────── 240   │   280 ───────────────────────── 1240         │
└──────────────────────────────────────────────────────────────┘
```

| 区域 | 取值 | 为什么 |
|---|---|---|
| 画布 | 1280×800 | 桌面端基准。**文档 ppi 必须设 72**（否则字号翻倍，见 `tokens.md` 单位纪律） |
| 侧边栏宽 | **240px** | 容纳 4 字导航 + 图标仍有富余；再窄换行、再宽浪费 |
| 内容带 `band` | **left 240 / right 1280** | 就是"侧边栏右边缘 → 画布右边缘" |
| 内容左右外边距 | **各 40px** | 于是内容区 x = **280 → 1240**，宽 **960** |
| 卡片内边距 | **24px** | 内容不贴边，又不显空 |

> **边距对称是最容易漏的一条**：只写左外边距、右边缘让内容自己撑，结果右留白 100px 而左只有 40px。**先定内容区左右边界，再往里填**，比反过来稳。

## 页头

| 元素 | 锚点 | 字号 / 字距 | 说明 |
|---|---|---|---|
| 标题 | `(280, baseline 76)` | 26px / tracking 20 | 内容区左上角起排 |
| 副标题 | `(280, baseline 106)` | 13px / tracking 60 | 与标题基线差 **30px**（约 17px 净间隙） |
| 主按钮 | `[1064, 56, 176, 44]` | 圆角 12 / 文字 15px | **右边缘 = 1240**，与内容区右边界对齐 |

> **按钮文字居中要按实测校正，不要按预算宽度摆**：产物导出的包围盒会向外取整（176→177、81→83），按估算宽度算必然差 1–2px。**先摆、再量、用 `layer.translate` 补差**，闭环一次就到 0.0px。

## 统计卡组

| 项 | 取值 | 为什么 |
|---|---|---|
| 卡片尺寸 | **304 × 132** | 3 张 + 2 个 24px 间隙 = 960，正好铺满内容区 |
| 卡片位置 | y = **148**；x = **280 / 608 / 936** | `x = 280 + i × (304 + 24)` |
| 卡片圆角 / 描边 | 圆角 **14** / 描边 1px `border` | 圆角 14 比 8 更柔和、比 20 更克制 |
| 标签 baseline | y = 卡顶 + **40** | 上内边距 24 + 一个字号高度 |
| 数值 baseline | y = 卡顶 + **88** | 与标签差 48px → 净间隙约 16px |
| 增量 baseline | y = 卡顶 + **118** | 与数值差 30px → 净间隙约 11px |
| 文字 x | 卡片 x + **24** | 与内边距一致 |

> **同一张卡里三段文字的基线间距（40 / 48 / 30）是净间隙的来源**，不是随便定的：改字号必须重算，否则 30px 字号会把标签压住 —— 实测 144ppiu 事故就是这么来的。

## 表格卡

| 项 | 取值 |
|---|---|
| 卡片 | `[280, 308, 960, 452]`，圆角 14 |
| 表头 baseline | 卡顶 + **41** |
| 表头分隔线 | 卡顶 + **68**，横贯整卡 |
| 首行 baseline | 卡顶 + **109** |
| 行距 | **52px** |
| 列位置 | 任务名 308 · 状态胶囊 `[780, 宽 68]` · 耗时 940 · 开始时间右对齐至 **1212** |

- **状态胶囊** = `68 × 26`，圆角 13（= 高度一半）；**底 = 语义「填充档」+ `alpha 0.18`**、**字 = 语义「文字档」纯色**（见 `tokens.md` §4 —— **不要用同一个色既当底又当字**，那样在 `accent` 上只有 2.97:1）
- 胶囊内文字 baseline **= 行 baseline**（胶囊 `y = 行 baseline − 17`，中心正好对齐）
- **时间列右对齐**：`HH:MM` 定宽，右对齐后纵列整齐；左对齐会看出参差

## 验证记录（这份配方的出处）

用本骨架产出的原型经 `check-ui-geometry` 判定（**78 层 = 49 文字 / 14 容器 / 15 装饰**）：

```
7 ✓ / 0 ❌    阈值：网格 8px · 最小间隙 4px · 居中 1px · 边距容差 1px
✓ ③ 49 个文字层无重叠
✓ ④ 同列文字最小间隙 14px（阈值 4px）
✓ ⑤ 8 个声明居中的元素偏差均 ≤ 1px
✓ ⑥ 内容区边距对称：左 39px / 右 38px
⚠ ⑦ 8px 网格符合率 7%（1/14）；该设计实际更接近 2px 网格（仅提示，可调 §4「UI 几何网格」）
```

> **两处"对不上"要主动说明，别当成没看见**：① 上表写的内容区边距是 **40px**，实测是 **39 / 38** —— 差在**导出的包围盒会向外取整**（±1–2px），不是设计走样；② 边距差 1px 仍在 `UI 边距对称容差` 内判 ✓，但**它确实不是绝对对称**。要严格对称就把内容区边界按实测回补 1–2px。
> 上面这组数字是**可复现的实测值**（同一产物重跑一致），不是估计。

> **⚠ 那一项是真的**：这份骨架**没有严格落在 8px 网格上**（卡片 y=148、行距 52、胶囊高 26 都不整除 8）。
> 它仍然"规整"，因为间距是**一致的**而不是**对齐网格的**。**要严格网格就把上表数字调到 8 的倍数**（148→144、52→56、26→24）；不调也能过门禁，因为网格项只判 ⚠ 不判 ❌。

## 移动端骨架（390 × 844 @ 72ppi，单列）

```
0   44  ┌─────────── 状态栏 44 ───────────┐
44  88  │ 顶部导航栏 44（标题居中）        │
88      │                                │
        │   ← 左右外边距 16px →           │
        │   卡片（内边距 20）             │
        │   卡片                           │
        │                                │
760 809 │ 底部标签栏 49                   │
809 843 │ Home Indicator 安全区 34        │
```

| 区域 | 取值 | 为什么 |
|---|---|---|
| 画布 | **390 × 844 @ 72 ppi** | 见 `tokens.md` §7；ppi 错了字号就错 |
| 内容左右外边距 | **16px** | 窄屏用桌面的 40px 会吃掉两成宽度 |
| 卡片内边距 | **20px** | 比桌面 24 略紧 |
| 卡片圆角 | **20px**（`radius-xl`） | 移动端卡片比桌面更圆才不显硬 |
| 卡片间距 | **16px** | 卡片之间 |
| 顶部导航栏 | 状态栏 **44** + 导航 **44** = **88**，标题 baseline **70** | 标题 17px 居中；右侧动作中心 y=66 |
| 底部标签栏 | 栏高 **49** + 安全区 **34** = **83**，顶边 y=**760**（占 760–809） | 图标 **20×20 顶边 y=766**；标签 12px baseline **802**。**别写 808** —— 12px 墨迹约 792–805，808 会跨进 809 安全区。**整列 97.5×49 就是可点区**，不要在 49 高里再塞两个 44 目标 |
| 列表行高 | **56**（单行）/ **72**（两行） | 低于 48 显挤且易误触 |
| 最小可点区 | **44 × 44** | 硬下限，图标视觉上更小也要撑够 |

> **移动端第一原则是「一屏只做一件事」**：桌面的侧边栏、多列、宽表格一律不能塞进 390px。要展示多列数据就改成卡片列表。

## 复杂度配方（要做"更像真实产品"的屏幕时用这些）

| 组件 | 取值 | 要点 |
|---|---|---|
| **环形进度** | 外径 **96**，描边 **8**，中心数字 **24px / tracking 0**，下方 caption **12px** | 12 点起、**顺时针**；轨道 = `border-strong`（α 0.10~0.14），进度弧 = 语义**填充档**（α 0.35~0.45）或纯色。**中心数字别用 34px**：外径 96 / 描边 8 时内径只有 80，34px 的百分比会顶到描边。中心文字必须实测居中（门禁 ⑤ 会判） |
| **柱状图** | 7 根柱，柱宽 **20**，间隔 **16**，绘图区高 **120**；底部日期标签 **12–13px** | **必须有 y 轴刻度或数值标注** —— 只有基线的话读者只能看出相对高低、读不出数。当前项用**纯色**、其余用**填充档**；刻度线用 `border-strong` |
| **分段控件** | 高 **32**，圆角 `radius-full`，选中背板 **内缩 2px** | 背板 = 填充档 @0.20，文字用**文字档**；不要用描边画选中态。**三格之间没有分隔时，未选中项会"漂浮"** —— 要么给格间 1px 分隔线（`border-strong`），要么把未选中文字用 `muted` 降一档 |
| **并排统计卡** | 3 张卡，间隙 **8**，内边距 **16**（不是 20） | 内容宽 358 时每张净宽只剩约 110，**内边距 20 放不下 4 位数字**（`0:28`）。数值用 **24px**（不是 30），标签 12–13px `muted` 在上 |
| **带头像的列表行** | 行高 **72**；头像 **40×40** 圆角 full、x=16；主行 16px、次行 13px `muted` | 头像与文字垂直居中；行尾放胶囊或箭头，**别放两样** |
| **徽标 badge** | 直径 **16**，数字 11px，或纯色点 **8** | 挂在图标右上，**外沿对齐**图标外沿 |
| **骨架屏** | 高度与目标元素**一致**，圆角**一致** | 填充 = `border-strong` 再减半（约 0.07α）；**骨架块的尺寸必须等于真内容**，否则加载完会跳版 |
| **空态** | 图标 **64×64**（`muted` @0.35），说明 15px，主按钮 44 高 | 图标-文案距 16，文案-按钮距 24；**空态不要出表头**，否则看起来像有数据但没加载出来 |
| **分区标题** | 13px / `muted` / tracking 60，上下留 16 | 用来切分长页面，比加分隔线轻 |
| **底部弹层（sheet）** | 宽 = 画布宽，顶角 `radius-2xl`，抓手段 **36×4** 居中 | 顶部抓手段是可点区，撑够 44 高；遮罩 = `#000` @0.5 |

## 现代化检查清单（"看起来旧"通常是这几条）

| 旧 | 新 |
|---|---|
| 到处画 1px **实色灰**边框 | 用**表面亮度差**分层（`bg`→`base`→`elevated`），描边用**低透明度白** |
| 正文与标题字号接近（14 / 16） | 拉开到约 **2 倍**（15 / 30） |
| 圆角统一 4–6px | 按尺寸给（控件 12 / 卡片 20） |
| 用同一个色既当底又当字 | **填充档 + 文字档**两档（`tokens.md` §4） |
| 小字不给字距 | 按 `tokens.md` §3 给 tracking |
| 全屏纯黑 `#000` 或纯灰 | 带一点色相的深色（`#0d1117` 系） |
| 阴影又大又黑 | 阴影要**小且低透明度**，或干脆用分层替代 |

## 怎么改（保留什么）

- **保留**：内容区左右边界先定、8px 间距阶梯、字号→tracking 映射、同类元素尺寸一致、**两层语义色**。
- **可改**：具体数值、配色（换成项目令牌）、卡片列数、是否要侧边栏、桌面端还是移动端骨架。
- **别丢**：改完**必须跑一次几何门禁**——重叠 / 过挤 / 不居中 / 边距不对称由 ③–⑦ 判，**看不清由 ⑧ 判**，都别靠眼睛。
- **颜色相关**：`tokens.md` 里那条"归一化浮点"陷阱（0–255 写成数组会静默变白）改配色时最容易踩。
