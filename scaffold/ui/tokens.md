# UI 设计令牌（通用默认值）

> **这是兜底，不是主张。** 它存在的唯一理由是：通用角色没有本项目的视觉语言，不兜底就会**每次现编一套**——而现编的设计系统看起来就是外行。
> **「规整」来自系统性，不来自品味。** 这张表就是把「系统性」固化下来。
> 表里的对比度数值都是**算出来的**，不是估的 —— 拿来就能用，且能过几何门禁的 ⑧。

## 优先级（硬规则）

1. `PROJECT.md` §4「**UI 项目令牌**」指向的文件（项目已有的主题 / 设计令牌 / 设计系统包）
2. 项目既有组件库的对外 `props` 与样式约定
3. **本文件**

**找到 1 或 2 ⇒ 照抄，不得发明。** 都没有 ⇒ 用本文件，并在交付里**写明「用的是默认令牌」**。

**禁止混用**：同一个包内不得一部分抄项目令牌、一部分用默认值 —— 那比全用默认更糟，会造出两套并存的语言。
**冲突时**：项目令牌与本文件不一致 ⇒ **以项目为准，并停下上报**（可能意味着本文件该更新）。

> **⑩ 会替你验「有没有照抄」，但只验到主题层** —— 配了「UI 项目令牌」后，
> 门禁 ⑩ 从令牌源抽出色板，要求**画面主色**（占画布 ≥0.5% 的那些）全部能由它推导出来
> （允许色板内两色按任意 α 叠加）。它抓的是「用了整套别的色板」这种硬伤 ——
> 实测把一个深色默认主题的屏配上浅色项目规范，⑩ 立刻点名 `#161b22`（56.7%）等主色。
>
> **它不管**：占比 <0.5% 的色，也就是**小字、描边、图标这些细碎用色**。
> 所以「⑩ 绿了」**不等于**"每个文字色都合规" —— 那一层由 **⑧ 对比度**兜（按渲染实测判）。
> 两者是分工，不是替代：**⑩ 管"用没用你的色板"，⑧ 管"这个色看不看得清"。**

---

## 0. 四条铁律（先看这个，再看下面）

1. **单位**：字号单位是 point，**随文档 ppi 缩放到像素**。要 `1pt = 1px`，文档分辨率**必须是 72 ppi**。设成 144 时 13pt 渲染成 26px，全部文字放大一倍塞进 1× 的间距里 —— 「字挤在一起」最常见的成因。
2. **填充色是归一化浮点**：批量填色的接口要 `0.0–1.0` 的浮点数组。给 `0–255` 的整数**不报错、直接变白** —— 静默失败，最费时间。
3. **双层语义色**：**同一个色不能既当底又当字**。填充用「填充档」（低透明度），文字用「文字档」（更亮的那个）。同色叠同色在 `accent` 上只有 **2.97:1**、`danger` 上 **3.91:1** —— 必然翻车。
4. **对比度要量，不要看**：排完版跑几何门禁，⑧ 会用产物像素算真实对比度。**「看不清的文字等于没有文字」**，而这件事是可量化的。

| `text-xl` | 20px | — | 小节标题 |
| `text-2xl` | 24px | 区块标题 | 页面标题 |
| `text-3xl` | 30px | 关键数值 | **关键数值 / 大标题（移动首选）** |
| `text-4xl` | 34px | — | 超大数字（环形中心、金额） |

> 70–110px，关键数值用 **24px**（`text-2xl`）；**环形中心**用 **24px**（外径 96 / 描边 8 时内径只有 80，

## 3. 中文 tracking 映射（**最容易被忽略、又最影响观感的一项**）

字体渲染不出来的差距，一半在字距上。**中日韩文字需要正字距，拉丁文不需要**；混排时按中文字号给值即可。

| 字号 | tracking（1/1000 em） | 等于 |
|---|---|---|
| 12px | **80** | 0.08em |
| 13px | **60** | 0.06em |
| 14px | **45** | 0.045em |
| 15px | **40** | 0.04em |
| 17px | **30** | 0.03em |
| 20px | 24 | 0.024em |
| 24px | 22 | 0.022em |
| 26px | **20** | 0.02em |
| ≥30px | 0 | 字号越大越不需要 |

> **越小的字越需要字距**。12px 中文不给 tracking 就会糊成一团 —— 这正是「字体挤在一起」最常见的成因。
> 表内没有的字号取**相邻更小档**（宁可多一点）。

## 4. 语义色：**每个色分两档**（这是最容易踩的坑）

**填充档**给底（胶囊 / 标签 / 选中态背板），**文字档**给字。两档都上表可查，且**对比度已核算**。

| 语义 | 填充档（底色） | 文字档（字色） | 文字档 on 胶囊底 | 文字档 on surface |
|---|---|---|---|---|
| `accent` | `#1f6feb` | `#79c0ff` | **7.21:1** | 8.89:1 |
| `success` | `#3fb950` | `#7ee787` | **7.97:1** | 11.26:1 |
| `warn` | `#d29922` | `#e3b341` | **6.32:1** | 8.89:1 |
| `danger` | `#f85149` | `#ff7b72` | **5.38:1** | 6.86:1 |
| `muted` | `#6e7681` | `#9ba7b4` | — | **7.07:1** |

**胶囊 / 标签的标准配方**（照这个做就不会翻车）：

```
底 = 填充档 @ alpha 0.18 ~ 0.20，叠在 surface 上
字 = 文字档（纯色，不加透明度）
```

> **⚠ 反例（我踩过）**：底用 `success` @0.22、字也用 `success` —— 名义上算出来 4.63:1 像是刚够，但
> **12px 中文笔画只有 1px 宽，渲染出来连通像素都被抗锯齿冲淡**，实测最亮像素只有 `#3aa84b`，
> 真实对比度掉到 **3.9:1**。同类配色在门禁 ⑧ 上一律报 ❌。
> **结论：小字的对比度必须留余量**，别贴着 4.5 走 —— 表里的值都留了 1.5 倍以上余量。
>
> **⚠ 数字比中文更吃亏**：**12px 的数字 / 拉丁**笔画比中文更细，实测 ⑧ 取最亮像素只有 **4.61:1**
> （贴着 4.5 走）。**数字类小字至少 13px**，或直接用更亮的一档。**别只给中文留余量。**

### ⚠ 小字要「再深一档」——标称达标 ≠ 渲染达标

**同一个色，字号越小，⑧ 量到的对比度越低。** 这不是门禁太严，是真实的物理效果：
小字号下笔画的抗锯齿像素占比高，采样到的有效像素里混进了更多底色，于是**渲染出来的对比度低于按标称色值算的值**。

实测（同一份真实项目规范、同一台机器）：

| 文字色 | 底色 | 标称算出来 | **12–13px 渲染实测** |
|---|---|---|---|
| `#5A6B85`（规范里的 muted 档） | `#FFFFFF` | **5.42:1** ✅ | **≈4.13:1** ❌ |
| `#5A6B85` | `#F7FBFF` | 5.21:1 ✅ | ≈4.0:1 ❌ |

**标称达标，渲染不达标 —— 差了约 1.3。** 这正好是「规范里明明写了达标色，画出来却被 ⑧ 判红」的根因。

**规则**：

1. **12–13px 的文字不要用 muted / 次要档**，直接用主文字档（`text`）。次要档留给 **≥14px**。
2. 判据一律以 **⑧ 的渲染实测**为准，**不要拿标称色值去和 4.5 比**：标称只能用来粗筛，筛完仍要跑 ⑧。
3. 反过来看，这条也解释了为什么 `-soft` 淡底上的文字几乎必挂：淡底本身已经吃掉一截余量（见下方「规范给的 Tag/Callout 配色可能本身就不过」）。

> **如果项目自己的设计规范提供了这组色**（L0），且它在小字上不达标：**照抄规范 + 显式声明偏离**，
> 不要偷偷改色，也不要改回通用默认。正确做法是「语义色只做底/点/图形，文字换主文字档」，
> 并在交付说明里写清偏离了哪一条、为什么。

### ⚠ 项目的 Tag / Callout 配色**可能本身就不过 AA**

真实项目的设计规范常把「深色字 + 同色系淡底」写成一对。**这一对经常是不达标的**，实测某真实规范：

| 规范给的配色 | 对比度 |
|---|---|
| `语义色-d` on `语义色-soft`（青绿） | **2.62:1** |
| `语义色-d` on `语义色-soft`（橙） | **2.62:1** |
| `语义色` on `语义色-soft`（红） | **3.13:1** |
| `语义色-d` on `语义色-soft`（琥珀） | **3.30:1** |
| `主色` on `主色-050` | **4.43:1** |

**这不是你抄错了，是规范本身的问题。** 处理方式同上：**底/点/图形照抄规范，文字换主文字档**，
并在交付说明里声明。**不要因为 ⑧ 判红就把产物改成通用默认配色** —— 那会同时丢掉项目令牌一致性（⑩ 会抓）。

### 填充档 α 对照表（**收敛成一张，别再各写各的**）

配方与实现里最容易散架的就是这个 —— 各处随手写 0.18 / 0.20 / 0.35，最后没人说得清为什么。

| 用途 | α | 为什么是这个值 |
|---|---|---|
| **文字底**（胶囊 / 标签 / 选中态背板） | **0.18 ~ 0.20** | 底要弱到不抢文字；再深就开始吃对比度 |
| **图形填充**（柱状条 / 进度弧 / 面积图） | **0.35 ~ 0.45** | 图形没有字形可依，太淡就**看不见**；这一档明显比文字底深是**故意的** |
| **强调图形**（当前项 / 最高值 / 选中图标） | **1.0（纯色）** | 一屏**只强调一处**，到处都是等于没强调 |
| **轨道 / 底线 / 分隔**（`border-strong`） | **0.10 ~ 0.14** | 只做参照，不参与读数 |
| **骨架屏** | **0.06 ~ 0.08** | 比描边再淡一半，避免和真内容混淆 |

### 中性色与表面

| 语义 | 值 | 用途 |
|---|---|---|
| `bg` | `#0d1117` | 页面底色（最底） |
| `base` | `#161b22` | 常规面板 / 卡片 |
| `elevated` | `#1c2129` | 抬起表面（弹层 / 悬浮卡） |
| `overlay` | `#22272e` | 最高层（模态 / 菜单） |
| `border` | `rgba(255,255,255,0.08)` | 常规描边 |
| `border-strong` | `rgba(255,255,255,0.14)` | 强调描边 / 分隔线 |
| `text` | `#e6edf3` | 主文字（14.64:1 on base） |
| `muted` | `#9ba7b4` | 次要文字（7.07:1 on base） |

> **现代化的一大半是「少用描边、多用分层」**：2020 年的做法是到处画 1px 实线边框；现在的做法是
> 用**表面亮度差**（bg → base → elevated）区分层次，描边只在需要**分组**时用，且用**低透明度白**而不是实色灰。
> 实色灰描边在深色底上会显得脏、硬。

| 页面左右外边距 | **16px**（`space-4`） | 窄屏不能用桌面的 40px |

| 顶部导航栏高 | **44 + 44 = 88** | 状态栏 44 + 导航 44（导航区 44–88，垂直中心 **66**） |

| 元素 | 取值 | 说明 |

| 导航栏标题 baseline | **70** | 17px 居中（导航区 44–88，中心 66） |

| 标签栏图标 | **20×20，顶边 y=766**（中心 776） | 24×24 会把可点列挤爆，移动端标签图标 20 就够 |
| 标签栏文字 baseline | **802**（12px / tracking 80） | **不要写 808** —— 12px 墨迹约 792–805，808 会让墨迹跨过 809 安全区界 |

## 8. 用法顺序（不是规矩，是顺序）

1. 先定**间距与字号**（决定观感的一半），再定颜色。
2. 每个文字层按 §3 给 tracking。
3. **颜色按 §4 的两档取，别用同一个色当底和字**。
4. 排完版**必须跑几何门禁**（`check-ui-geometry`）—— 重叠 / 过挤 / 不居中 / 边距不对称由 ③–⑦ 判，**看不清由 ⑧ 判**，都别靠眼睛。
5. 顺序反了（先调色再排版）会反复返工。
