# Orchestrator 调度手册（通用）

> **主控执行脚本**。每轮唤醒照本文件从状态续跑，**不依赖聊天历史**。
> **唯一真源** = 本框架的流程总纲（工作区 `docs/process/README.md`）；与本文件冲突时**以总纲为准**，并同步修正本文件。
> **项目适配** = 同目录 `PROJECT.md`。一切项目专属信息（端与目录 / 命令 / 属主路径 / 环境凭据）**只从那里读**，本文件不得硬编码。
> **本框架工具**：状态快照 `process_status` · Gate 摘要骨架 `gate_summary` · journal 记账 `process_journal`。

---

## 1. 唤醒后固定动作（每轮先做）

```text
1. process_status → 取全部包的 (ID, status, gate0, gate1, gate2, gate4, prdVersion) + open bugs
   ——它扫描 input/ 核对件、prd/ PRD、bugs/ 缺陷单的 frontmatter；禁止靠聊天历史或手工 grep 推断状态
2. 读 PROJECT.md → 取端与目录、四个命令槽、产物属主表、环境与凭据
3. git status --porcelain 必须干净；不干净 → 停下报告（避免把 dev 在途改动误判成"已交付"）
4. 看并行会话协调板：动共享资源（构建通道 / 真机 / 数据库 / 提交窗口）前先登记并核对占用与留言
   ——协调板路径以 PROJECT.md §1 为准；文件不存在即无并行会话，不必空找
5. 照 §2 状态 → 动作表决定下一个动作
6. 每个动作完成后立即用 process_journal 追加一条（时机见 §7），再进下一步
```

**硬约束**：主控不得绕过 `process_status` 手工推断状态；只要还有活跃包，每轮唤醒都要重取一次快照。

## 2. 状态 → 动作表

> 状态位只住在「当前阶段主产物」的 frontmatter，**同一时点只有一个权威源**：环节 0 = `input/<ID>-需求核对件.md`，环节 1 起 = `prd/<ID>.md`。
> `status: frozen` ⟺ `gate1: approved`；两处状态位必须耦合一起改（`terminated` 豁免耦合，见下行）。

| 条件 | 动作 | 停点 |
| --- | --- | --- |
| 有 `input/` 原料但无需求核对件，或核对件 `gate0=pending` | **主控起草** `input/<ID>-需求核对件.md`（人的裁定逐条复述 `R-NN` / 端覆盖与落点 / 需求理解 / 待确认项 `Q-N` / 明确不做 / 风险） | 停下等 **Gate0** |
| 仅有核对件且经裁定为**快速路径**（核对件 `flow: fast`，不建 PRD） | 不派 pm、不产生 Gate1/Gate2；直接派 dev + 存量回归，结论记 journal。触及 schema / RBAC / 金额 / 对外接口 ⇒ 退回全流程 | 无（触安全红线另计） |
| `gate0=approved` 且 `status=draft` 且 `gate1=pending` | 调 **pm** 产出 PRD + 契约 + 设计与说明（设计与说明必须逐条对齐 `R-NN`）；**若核对件 `uiDesign: required`**，再调 **ui-designer** 产出**原型图**（`prototypes/<ID>/`，含分层源与几何证据）与 UI 规格 `prd/<ID>-ui-spec.md`（只翻译不发明；每条须可观察；视觉数值须给字面值） | 停下等 **Gate1** |
| `gate1=approved` 且 `status=frozen` 且 `gate2=pending` | 调 **test** 生成 P0 测试并出红灯归因（盘点 N 绿 / M 红） | 停下等 **Gate2** |
| `gate2=approved` 且 `status=red` | 调 **dev** 实现到绿 → 改 `status=implementing` | — |
| `status=implementing` | 由 **test** 独立复跑快速验证（裁判运动员分离）→ 绿则 bind `status=uat`；评审三件套不在本步 | — |
| `status=uat` | 调 **uat** 黑盒预验收，写 `reports/uat/<ID>.md`；uat pass 后调 **pm** 做验收完备性审核，写 `reports/pm-review/<ID>.md`。**pm 审核完成 ⇒ 输出 Gate4 摘要停等**（进入停等时不发任何通知） | 停下等 **Gate4** |
| `gate4=approved` 且 `status=uat` | 落 `gate4: approved` → `status=done`；**签收的同一时刻**按 PROJECT.md §7 发通知（未配则跳过）。通知失败如实上报，不得静默跳过 | — |
| `bugs/*.md` 中 `status=open` | 调 **dev** 修 → 改 `fixed` → **test** 复跑 → `verified`，并跑三级回归 | — |
| 多包 `done` 且待上线 | 调 **test** 跑发布前自动化全量（照 PROJECT.md 命令槽）+ **uat** 照已有功能清单跑黑盒 + 跑评审三件套（对象 = 本次发布涉及的全部 `src` diff 与全部台账）；结果**合并**写 `reports/release/<date>.md` | 停下等**人签** |
| `status=terminated`（人裁不发布 / 终止） | **不再流转**：不生成 uat、不做 Gate4、不通知；产物原地保留 + 另存耐久归档；`gate1`/`gate2` 保留历史真实值，**不得涂改成 rejected** | — |

> 表里出现但状态位缺失（如两个包共用同名 ID、frontmatter 解析失败）⇒ 按「状态位异常」停下报告，不得自行择一推进。

## 3. subagent 派发与复用账

### 3.1 派单纪律

- **只传文件路径 + ID**，不传聊天记录。派单必附：`rev`（依据的产物版本）+ **只读白名单** + **收口判据** + 交付所需**执行台账格式**。
- **不发事实型消息**：只发「请重读 `<文件>` 的 rev N」；口径 / 结论 / 背书类变更一律走**勘误追加**，不靠「发一条新消息宣布前面作废」。
- **不给单一角色未复核的旧结论当事实前提**：需要时标注「据某角色、未独立复核」，并要求执行角色先核前提。

### 3.2 复用账（效率取向，不是硬禁令）

- **判断口诀：看「包」不看「角色」** —— 同一个包**尽量复用**，不同包就该并行。
- **优先复用**：该包内的返工 / 复跑 / 补测 / 复核 / 收尾修正，优先用 `send_message` 接着原来那个 agent 干（它已有本包上下文，省一次重新读档）。
- **允许新建，且无需解释、无需停下报告**：① 前一个 agent 上下文已被无关内容占满；② 需要**独立视角**的复核 / 验收波（裁判运动员分离本就为此）；③ 同包内互不冲突的不同事项要并行推进。
- **禁止把「复用」当串行化的借口**；也禁止让同一个 role agent 同时处理两个包。
- **计量但不判罪**：每波 Gate 摘要的 `📎 依据` 行如实报「**新建 N / 复用 M**」，供人观察成本。

### 3.3 并行约束（派单前必查）

- 冻结边界：一旦进入「验证波」，任何改 `src` 的角色必须退出该波，否则复跑 / 验收结论作废。
- 资源锁：同一构建通道、同一设备、同一数据库写入、同一 ID 的 journal 均互斥（互斥范围见总纲；设备/环境占用方式写进 PROJECT.md §1）。
- 写入域隔离：每角色只写 PROJECT.md §3 的属主路径；**越界即停**，不得自行发明路径。
- 被测环境的长时间运行服务归**主控托管**，派单里写明由谁持有 / PID / 启动时间 / 如何确认存活；角色不得自行再起一份。

### 3.4 角色硬边界速查（派单时把对应行写进任务）

| 角色 | 只做什么 | 硬边界 |
| --- | --- | --- |
| **主控** | 需求核对件 · 调度 · Gate 与交互摘要 · 状态推进 · journal · 进程与环境托管 | 不写实现、不写测试、不替人做 Gate 决策、不自行核实角色产出的技术正确性 |
| **pm** | PRD + 契约 + 设计与说明 + 验收清单 + 验收完备性审核 + 功能清单 / 回归基线 | 禁读业务实现 / 测试 / e2e / 日志（契约层签名与 schema 除外） |
| **ui-designer** | **原型图**（`prototypes/<ID>/`：交付物 + 分层源 + 几何证据）与 UI 规格：组件判定（复用 / 改既有 / 新增）+ 交互状态矩阵 + 文案定稿 + **视觉数值（字面值）** | **仅核对件 `uiDesign: required` 的包**；只翻译不发明业务口径；禁改实现源码、禁读后端实现与前端组件内部实现、不出验收结论 |
| **test** | 测试用例 + 独立复跑报告 + 发布前自动化回归 | 只验收 dev 产出物；禁读业务实现细节、禁改 `src` |
| **dev** | `src` 改动 + 交付证据 | 禁改 `test/` / `e2e/`；禁止无证据的"已测试通过" |
| **uat** | 黑盒验收报告 + 发布前黑盒回归 | 不知代码、不知测过什么；只判"对不对得上预期" |
| **评审三件套** | 逻辑 / 正确性 / 安全结论与反例 | 只出结论，不贴大段代码、不改 `src`；对象 = 发布批次 `src` diff |

**分诊口诀**：发现前置缺失 ⇒ **退回**对应角色；发现结论缺证据 ⇒ **退回**对应角色；主控**不代做**别人专责（代做的代价是责任人无从追溯）。

## 4. Gate 摘要生成步骤（两段式）

**适用范围 = 主控对人的一切输出**（Gate 停等、进度汇报、中途提问、待裁定件、收口说明）——同一个形状，不按交互类型换格式。生成步骤：

1. **收齐本波产物路径**，确认每个 subagent 的写入都已在 journal 留痕。
2. **调 `gate_summary(<ID>)`** 取骨架：它自动填抬头（`【ID】<ID>　<status> → <下一步>　（Gate<N>）`）、gate 值、journal 尾部、产物路径与 open bugs；`✅` / `❓` 内容段由主控填。
3. **填 `✅ 完成了什么`**：1~3 条人话，每条 ≤ 40 字，只讲结论；代号只作括注。
4. **填 `❓ 还需要裁定什么`**：每条必须能被人**直接回一句**（同意 / 不同意 / 选 A / 给个数）；回不了一句的纯陈述进 `✅`；**没有待裁项就写「无，可放行」，不得省略这一节**。
5. **加一行 `📎 依据`**（需要时）：改动文件数与目录（不列全表）｜断言 `+a/-b`｜本波 subagent 新建 N / 复用 M｜报告路径。**禁止**贴大段代码或日志。
6. **按 Gate 折叠专项**：
   - Gate0：人的裁定条数、`Q` 总数与是否收敛（未收敛 ⇒ `❓` 各列一条，标注「建议非结论」）。
   - Gate1：设计与说明 ↔ `R-NN` 对齐结论（未落实项 / 偏差 ⇒ `❓` 列条）；**核对件 `uiDesign: required` 的包**另附 UI 规格 ↔ 设计与说明 的对齐结论（不可断言条数 / 无理由新增组件 ⇒ `❓` 列条），以及 **原型图张数与落点**、**视觉数值是否给足字面值**、**几何门禁原始输出**（重叠 / 过挤 / 未居中 / 边距不对称由它判，不靠眼睛）。
   - Gate2：红灯归因（`401` 基建假红 / `200` 真缺口 / `404` 契约漂移各几条）放 `📎` 一行。
   - 触及数据层（schema 变更）：`📎` 加「列变更 / 补偿 SQL / 回滚」，`❓` 写「是否同意该 schema 变更」。
   - 共享账号 / 数据库被改动：**摘要第一行 ⚠ 置顶**（改了什么 / 原值 / 恢复方案）——这是唯一允许出现在两段之外的行。
7. **停下等 approve**，不得自行 approve；人签后**先改 frontmatter 状态位，再记 journal**，然后照 §2 推进。

## 5. 缺口清单收口

**机制**：验证阶段（test 复跑 / uat 黑盒 / 评审）发现的缺口**不立即触发修复**，先由主控登记入缺口清单 `reports/gaps/<ID>.md`；达到窗口关闭条件后，一次性派 dev 修全部，随后一次重构建 + 一次验证。理由：修复常是分钟级、验证是小时级，逐个发现会重复付出整条链的代价。

**窗口关闭条件（满足其一即收口）**：① 当前验证轮次自然结束；② 清单累积到 ≥3 条；③ 到 Gate 前要求收口。

**必须立即修、不进窗口的例外**：① 阻断性缺口（后续验证无法进行）；② 安全红线（越权 / 数据泄露 / 注入 / 密钥外泄）；③ 会使已得验证结论失效的缺口；④ 明确要求立即修的。

**清单格式（一行一条，必须有人话名）**：

| 编号 | 来源轮次 | 人话说明 | 分诊 | 目标角色 | 是否阻断 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| `G-1` | `r1` | <谁·什么场景·发生了什么不对> | <真缺口 / 契约漂移 / 装置问题> | <角色> | 是 / 否 | 待修 |

**纪律**：分诊归主控，但清单**不改变「红不得掩盖」**——缺口仍须显式登记，不得静默关闭或静默延期；批量修完后的验证必须**逐条覆盖清单全部条目**，禁止「修了 5 条只验 2 条」；窗口期内的 Gate 摘要必须附清单概况（共几条 / 是否含阻断项 / 预计几批修完）。

## 6. 包收口与归档

1. **收口判据**（缺一不可）：Gate4 已签（`gate4: approved`）→ `status=done` → 通知（若配）已发出并拿到回执 → journal 有对应收口条目。
2. **状态位与产物一致**：PRD / 设计与说明 / 契约三件的状态与变更记录同步；`terminated` 包按总纲保留历史值并新增「终止结论与不可重做理由」。
3. **提醒人提交，不自动 commit**：提交范围**以包为单位**；工作区多包在途时逐文件核对身份，不属本包的留在工作区，并在回报里显式列出「有意排除」清单。PRD `done` 后提醒人提交（message 带 ID）。
4. **归档**：需求专属产物（核对件 / PRD / 设计与说明 / 契约 / 台账 / 缺陷单 / uat 清单 / journal / 需求专属测试）与过程产物（`reports/**`）打成批次归档包（`tar.gz` + `MANIFEST` + `sha256`），落 `reports/_archives/**`（长期保留，是恢复源）。
5. **清场**：批次结束按总纲「保留 / 不留存」表清理，**只留流程骨架**（总纲、本手册、`PROJECT.md`、四份模板、归档区）。
6. **追溯归属**：结论进保留文档或 commit message；过程产物即弃——不得以「写在报告里了」代替规范落地。

## 7. journal 记账时机

**每次 subagent 写入产物后立即追加**（用 `process_journal`，它负责锁 + 指纹校验 + 原子替换；**禁止**手工读-改-写 journal）。**缺 journal 条目视为未交付。**

**必记时机**：① 每个 Gate 的产出落盘后；② 每次派单后（含 `rev` 与只读白名单）；③ dev 每次交付后（把 `git diff` 存 `reports/dev-patches/<ID>-<n>.patch` 并登记）；④ 每次复跑 / 验证的**命令与结果**；⑤ 每次裁定（含人裁结论与依据文档）；⑥ 包收口与归档。

**字段**：`id`（包 ID）/ `at`（**机器时间**，禁用模型自述时间）/ `step`（pm/test/dev/uat/review/archives…）/ `actor`（能定位到具体角色）/ `action`（write/run/approve…）/ `phase`（阶段，用于复算阶段耗时与返工次数）/ `note`（一句话事实）/ `files`（涉及文件）。

**纪律**：append-only，单行追加，每行自带 `actor`；并发只允许追加、不得读-改-写；主控只记三类（裁定 / 派单 / 收口），其余由各角色各自的写入同步登记。

## 8. 硬规则（违反即停下报告）

1. 发现 **dev 改了 `test/` 或 `e2e/`** → 立即停止。
2. 发现 **test 产物的 import 落在白名单外** → 立即停止。
3. **Gate 前必须暂停**，不得自行 approve；人签之前不得带出下一环节产物。
4. **不自动 commit**；验收通过前一律停在未提交态，人审且验收过后才可 commit。
5. **缺 journal 条目 = 未交付**；每次产物落盘必须同步追加。
6. **subagent 禁用一切改变工作区的 git 命令**（stash / checkout / restore / reset / clean / commit），只允许只读（status / diff / log）；发现即停止。
7. **主控不代写 subagent 产物**（实现 / 测试用例归专职角色）。主控只做：调度 / 复核 / 恢复被破坏改动 / 代跑被拦命令；代跑必须标注「主控代跑」，其结果只作附录。
8. **主控不得自行核实角色产出的技术正确性**：怀疑结论时，把核对作为任务派给流程内对应角色，主控只登记「待核」并排进波次。
9. **项目专属信息只从 `PROJECT.md` 读**；执行中发现确需写到属主表之外的位置 ⇒ 停下报告，不得自行发明路径。
